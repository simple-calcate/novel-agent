# ADR 0009: 墨枢写作协议作为训练数据契约

## 状态
已接受（v2）

## 背景

块模型已把章节切成思考 / 正文，导出按「思考段 → 随后正文」配对。这只解决了**切层**，没有解决**数据质量**：

- 思考是自由文本，模型分不清作者决策、角色内心和设定百科。
- ShareGPT 的 human 侧写死「继续写作」，续写任务的上文丢失。
- 无思考的正文仍进训练集，看不出这一拍为什么这样写。
- 思考与正文串层（草稿互拷、作者注进正文）没有过滤器。
- v1 把上文截成约 600 字正文、丢掉历史思考，续写对不齐「从章首读到光标」。
- 思考里的 `@` 若绑成正史实体，会把尚未审核的词表当成数据库主键。

网文 Agent 的长期价值取决于作者日常写作能否稳定产出可训练样本，而不是事后从纯正文反推思维链。

## 决策

1. 把「思考 / 正文 / 拍」的语义写成 [写作协议](../../writing-protocol.md)，编辑器、导出器、续写系统提示共用。当前版本为 **v2**。
2. **拍**是训练原子：连续思考 + 紧随正文。不把拍做成第三种存储实体，避免作者维护三套结构。
3. 思考用可选行首槽位（意图/约束/手法/兑现/禁止）；导出时解析，写作时不弹强制表单。
4. 每条样本的上文从**本章开头**排到本拍之前，思考标 `【思考】`、正文原样，**不截断**。禁止零信息 human。
5. 当前拍思考只出现在助手侧。用户侧是章首到上一拍的全部内容（含历史思考），不含本拍思考。
6. `@` 插入的是写作标签（人物/伏笔/地点/道具/势力/规则），身份是词表而不是 `CanonEntity`。以后可再拆成工具调用。
7. 导出默认丢弃 `skip`（无思考、过短、串层）。权威实现在 `novel-domain::protocol`，前端镜像一份供即时统计。

## 后果

- 作者按协议写，导出即可用；不按协议写，样本被降级或跳过，质量不会被数量稀释。
- 槽位是约定不是 schema，解析对同义标签（目标/限制/写法）容错，未标注的思考仍可进 `usable`。
- 长章的上文会变长；这是有意选择，优先保真，不在协议层做滑窗。
- 正史快照仍不打进每条 jsonl，避免未审核候选污染训练；标签也不预绑实体 id。
- 前端与 Rust 双份实现需要成对改测试；以 domain 单测为语义基准。
- 完整样章见 [雾港来客](../../examples/fog-harbor.md)。软件里「打开示例章节」装的是同一份；协议改语义时样章测试必须一起过。
