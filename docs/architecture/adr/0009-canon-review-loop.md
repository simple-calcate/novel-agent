# ADR 0009: 预先设计的结构，按当前段落匹配

## 状态
已接受

## 背景
写作时需要看见**已经设计好**的人物、设定、伏笔，而不是从正文现抽。这些结构由作者事先写入；编辑器只把当前段落和它们做匹配，按相关度排在上方。

## 决策
- 作者在右侧「结构」里添加三类条目：人物、设定、伏笔。写入即生效，不走抽取/审核。
- `context.hints` 用当前段落匹配这些条目，信号按强度是：全名 > 别名 > 长标题的词核（如「雾中灯塔」里的「灯塔」）> 设定关键词（从说明里拆出的「刀客」「旧王玺」这类）。上一段出现过的人名会短暂留在预选里。
- 匹配结果作为预选条排在编辑器**上方**，卡片上写出命中原因。
- 仓储：`story_entries` 独立保存预先结构，不和启发式抽取混在一张表里。抽取 API 仍保留，但不是这条产品路径。

## 后果
- 没有预先结构时，上方预选为空。
- 伏笔不会在无关段落里刷屏；只靠设定关键词或标题词核命中时分数更低，全名仍优先。
