# 产品：现在怎么写

墨枢是本地优先的网文写作桌面应用。正文、结构和队列都在本机 SQLite。没有预先结构时，编辑器上方预选条为空，这是预期，不是故障。

浏览器预览（`pnpm --filter @novel-agent/client dev`）能写、能建树，数据在内存里，关页即丢。桌面（`pnpm tauri dev`）才持久化。

## 界面

```
┌────────────┬──────────────────────────┬──────────────┐
│ 当前作品   │ 章标题 · 修订号 R n      │ 上下文       │
│ 书 / 卷 /  │ 预选条（钉住 / 忽略）     │ 结构 ← 主路径 │
│ 章 树      │ 本章场次                  │ 工作流       │
│ 新章节     │ 续写预览（接受 / 拒绝）   │ Agent        │
│ 设置 · 日志│                          │              │
└────────────┴──────────────────────────┴──────────────┘
```

- **左侧**：作品选择、书/卷/章树。树节点的改名、删除、上下移只在**悬停**时出现，避免挤掉标题。点「打开示例章节」会装进《雾港来客》三拍样章。
- **中间**：当前章。默认写正文；空行 `Tab` 切到思考。上方预选条按当前段落匹配结构。顶栏「续写」出预览条。
- **右侧默认「结构」**：作者预先写入人物、设定、伏笔。
- **「上下文」**：三步口令（先写思考 → 再写正文 → 一小段一小段），不是抽取结果。
- **「工作流 / Agent」**：队列与续写相关；Agent 页会显示已记下的偏好条数。
- **左下角设置**：模型 provider / 地址 / 模型名 / API Key。

顶栏「检查」会入队 `continuity.check`，走的是库内正史连续性工具，不是结构预选条。

## 作品库

层级是 **作品 → 书 → 可选卷 → 章 → 可选场**。

| 操作 | 行为 |
|---|---|
| 点中卷再「新章节」 | 章挂在该卷下 |
| 点中书再「新章节」 | 章直接挂在书下 |
| 书里已有卷、章没有卷 | 这些章出现在「未分卷」 |
| 删卷 | **不删章**，只把 `volumeId` 清空，章回到书下（有其它卷时进「未分卷」） |
| 章下「新场」 | 只给这一章加大纲标题，**不改正文** |
| 删场 | 只删大纲，正文留下 |
| 删书 / 删作品 | 下属一并删除（确认框会写清对象） |

卷只分组，不是必填。没有卷时，章直接列在书下，不出现「未分卷」标签。

打开一章后，编辑器预选条下方是 **本章场次**。场是章内大纲（标题、顺序、可选 POV 人物），不是正文分段。

## 结构（写作主路径）

右侧「结构」里由作者预先写入三类条目：人物、设定、伏笔。

- 标题可写成 `林晚、雾儿`：入库后主名是 `林晚`，别名是 `雾儿`。
- 说明（summary）会参与关键词匹配，例如「雾港来的刀客」。
- 写入即生效，**不走正文抽取、不走审核闭环**。
- 启发式抽取 API（`propose_canon_*`）还在代码里，界面不用。

没有条目时预选条隐藏，编辑器仍可写正文。

## 思考与正文

空行按 `Tab` 切到思考。思考里写这段要干什么，并用 `@` 点人物、伏笔——那是写作标签，不等于结构库里的实体。再 `Tab` 回去写读者看到的小说。完整样章见 [雾港来客](../examples/fog-harbor.md)，约定见 [写作协议](../writing-protocol.md)（[ADR 0011](../architecture/adr/0011-writing-protocol.md)）。

## 当前段落预选

编辑器上方是预选条（`ContextRail`），按**当前段落**匹配结构条目，按相关度排序，卡片上写命中原因。光标换段会立刻重算。

信号从强到弱：

1. 当前段出现全名
2. 出现别名
3. 长标题的词核（「雾中灯塔」→「灯塔」）
4. 说明里拆出的关键词（「刀客」「旧王玺」），去掉停用词
5. 上一段出现过的人名会短暂留在预选里（dwell）
6. 本地没命中时，用当前段里的词去条目标题/说明做词汇检索（例如说明写「负责在雾季敲钟」，正文写「雾季快到了」）

桌面走 Rust `context.hints`。浏览器预览没有 Tauri 时走前端 `matchStoryEntries`。两边共用 `packages/match-fixtures/cases.json`。卡片可钉住或忽略（记在本机 `localStorage`）。LLM 重排还没有。

## 续写与偏好

左下角设置模型。API Key 不会回显明文；已保存时输入框留空表示保持原值。续写请求本身不带密钥，由桌面宿主从密钥库填入。

拒绝一次 AI 续写会记下一条作者偏好；下次续写把未停用的规则写进 system prompt。同一条规则文本被拒绝两次会升为 Confirmed。右侧 Agent 页可以查看并停用。接受续写则把预览写入正文。

左下角「插件」列出打包清单。打包项走内置执行器。第三方把 AssemblyScript guest 用 `@novel-agent/plugin-compile` 编成 WASM，清单带 `wasmBase64` 时桌面在 wasmi 沙箱里跑（无 WASI、无文件系统）。Android 仍是内置。

工作流页可以把待发送 outbox 写成应用数据目录下的 JSONL。这是本机 journal，**不是**手机和电脑之间的同步。

## 作者保证

- 稿子默认只在本机。没配模型也能写。
- 以后若有同步或订阅，到期后仍能打开、编辑、导出已经在电脑上的正文。
- API Key 不进作品库。插件没有默认的文件系统权限。

完整条文见 [作者保证](trust.md)。写插件见 [写插件](plugins.md)。许可切开见 [许可](licensing.md)。

## 明确不是什么

- 不是「从本章提取人物再请作者审核」。
- 不是多人实时协作。同步传输还没做；工作流页可以把 outbox 写成 JSONL。
- 不是必须联网才能写。没配模型时仍可编辑本地正文。
- 场次不是从正文自动切出来的，要作者自己加。
