# 产品：现在怎么写

墨枢是本地优先的网文写作桌面应用。正文、结构和队列都在本机 SQLite。没有预先结构时，编辑器上方预选条为空，这是预期，不是故障。

浏览器预览（`pnpm --filter @novel-agent/client dev`）能写、能建树，数据在内存里，关页即丢。桌面（`pnpm tauri dev`）才持久化。

## 界面

```
┌────────────┬──────────────────────────┬──────────────┐
│ 当前作品   │ 章标题 · 修订号 R n      │ 上下文       │
│ 书 / 卷 /  │ 预选条（有命中才出现）    │ 结构 ← 主路径 │
│ 章 树      │ 正文编辑器               │ 工作流       │
│ 新章节     │ 续写预览（接受 / 拒绝）   │ Agent        │
│ 设置 · 日志│                          │              │
└────────────┴──────────────────────────┴──────────────┘
```

- **左侧**：作品选择、书/卷/章树。树节点的改名、删除、上下移只在**悬停**时出现，避免挤掉标题。
- **中间**：当前章正文。上方预选条按当前段落匹配结构。顶栏「续写」出预览条。
- **右侧默认「结构」**：作者预先写入人物、设定、伏笔。
- **「上下文」**：说明性卡片，不是抽取结果。
- **「工作流 / Agent」**：队列与续写相关；Agent 页会显示已记下的偏好条数。
- **左下角设置**：模型 provider / 地址 / 模型名 / API Key。

顶栏「检查」会入队 `continuity.check`，走的是库内正史连续性工具，不是结构预选条。

## 作品库

层级是 **作品 → 书 → 可选卷 → 章**。

| 操作 | 行为 |
|---|---|
| 点中卷再「新章节」 | 章挂在该卷下 |
| 点中书再「新章节」 | 章直接挂在书下 |
| 书里已有卷、章没有卷 | 这些章出现在「未分卷」 |
| 删卷 | **不删章**，只把 `volumeId` 清空，章回到书下（有其它卷时进「未分卷」） |
| 删书 / 删作品 | 下属一并删除（确认框会写清对象） |

卷只分组，不是必填。没有卷时，章直接列在书下，不出现「未分卷」标签。

## 结构（写作主路径）

右侧「结构」里由作者预先写入三类条目：人物、设定、伏笔。

- 标题可写成 `林晚、雾儿`：入库后主名是 `林晚`，别名是 `雾儿`。
- 说明（summary）会参与关键词匹配，例如「雾港来的刀客」。
- 写入即生效，**不走正文抽取、不走审核闭环**。
- 启发式抽取 API（`propose_canon_*`）还在代码里，界面不用。

没有条目时预选条隐藏，编辑器仍可写正文。

## 当前段落预选

编辑器上方是预选条（`ContextRail`），按**当前段落**匹配结构条目，按相关度排序，卡片上写命中原因。光标换段会立刻重算。

信号从强到弱：

1. 当前段出现全名
2. 出现别名
3. 长标题的词核（「雾中灯塔」→「灯塔」）
4. 说明里拆出的关键词（「刀客」「旧王玺」），去掉停用词
5. 上一段出现过的人名会短暂留在预选里（dwell）

桌面走 Rust `context.hints`。浏览器预览没有 Tauri 时走前端 `matchStoryEntries`。规则应对齐，但两套实现，改匹配时要两边一起改。

## 续写与偏好

左下角设置模型。API Key 不会回显明文；已保存时输入框留空表示保持原值。续写请求本身不带密钥，由桌面宿主从密钥库填入。

拒绝一次 AI 续写会记下一条作者偏好；下次续写把未停用的规则写进 system prompt。同一条规则文本被拒绝两次会升为 Confirmed。Agent 侧栏显示当前偏好条数。没有单独的偏好管理界面。

接受续写则把预览写入正文。

## 明确不是什么

- 不是「从本章提取人物再请作者审核」。
- 不是多人实时协作。同步传输还没做；本机只把变更写入 outbox。
- 不是必须联网才能写。没配模型时仍可编辑本地正文。
